# StuKit 课表模块开发计划

## 1. 模块目标

课表模块用于个人维护学期课程并按周查看安排。首个版本继续优先支持 Windows，同时
保证 Domain、Application、Repository 接口和主要 QML 组件可以迁移到 Android。

课表与记账属于两个独立功能模块。它们共用应用外壳、主题、SQLite 连接和迁移机制，
但不互相依赖业务实体或用例。

## 2. MVP 功能范围

### 必须完成

- 创建、编辑、归档和切换学期。
- 创建、编辑和删除课程。
- 保存教师、教室和课程颜色。
- 为课程设置星期、起止节次、起止周和每周/单周/双周规则。
- 按指定教学周查看周课表。
- 检测同一学期内实际周次和节次重叠的课程。
- 通过 SQLite 持久化，并随应用重启恢复。
- 正确处理空课表、跨周范围和归档学期。
- 在 Windows 宽窗口与 Android 窄窗口使用同一套业务数据。

### 暂不实现

- 教务系统或 Excel 自动导入。
- 系统日历同步。
- 桌面小组件和上课提醒。
- 多设备云同步与登录。
- 调课、停课和临时补课例外。
- 成绩、作业和考试管理。

这些功能以后可以建立在稳定的课程与上课安排模型上，不应提前混入 MVP。

## 3. 核心领域模型

### `AcademicTerm`

表示一个学期：

- 稳定 UUID。
- 学期名称。
- 开始日期。
- 总周数。
- 是否归档。

开始日期决定第 1 周的日期范围。总周数限定课程安排允许使用的最大教学周。

### `Course`

表示一门属于某学期的课程：

- 稳定 UUID。
- 所属学期 UUID。
- 课程名称。
- 教师。
- 教室。
- 稳定的 `#RRGGBB` 显示颜色文本。

颜色在 Domain 中是可验证、可持久化的字符串，不依赖 QML `color` 或 `QColor`。

### `CourseMeeting`

表示一门课程的一个重复上课安排：

- 稳定 UUID。
- 课程 UUID。
- 星期一至星期日。
- 起始节次和结束节次。
- 起始周和结束周。
- 每周、单周或双周。

同一门课程可以有多个安排，例如周一第 1～2 节和周三第 3～4 节。

### 后续值对象

界面进入具体时间显示前，再增加节次定义，例如“第 1 节 08:00～08:45”。课程冲突
以教学节次为准，不以像素坐标或文本时间直接判断。

## 4. 冲突规则

两个上课安排只有同时满足以下条件才冲突：

1. 关联课程属于同一学期。
2. 星期相同。
3. 节次闭区间重叠。
4. 起止周范围存在交集。
5. 交集内至少有一个周次同时满足双方的每周/单双周模式。

例如单周第 1～16 周和双周第 1～16 周不冲突；单周第 1～16 周与每周第 1～8 周会
在第 1、3、5、7 周冲突。

单个实体只验证自身是否合法。查询其他课程并生成冲突列表属于 Application 用例。

## 5. 架构与目录

```text
src/features/schedule/
  domain/          实体、枚举、Repository 接口
  application/     创建、修改、查询和冲突检测用例
  infrastructure/  SQLite Repository 与数据映射
  presentation/    ViewModel 和 QML 列表模型
  qml/             课表页面、表单和周视图组件
```

依赖方向：

```text
QML -> Presentation -> Application -> Domain
Infrastructure --------------------------> Domain
```

课表 Domain 不依赖记账 Domain。真正跨模块且已经稳定的能力才进入 `shared/`。

## 6. 数据库初步设计

MVP 预计新增表：

```text
academic_terms
courses
course_meetings
```

可自定义每节课起止时间进入正式需求后，再通过独立迁移增加
`period_definitions`，不提前创建暂时没有 Domain 与用例使用的表。

关系：

```text
AcademicTerm 1 ---- N Course 1 ---- N CourseMeeting
```

- UUID 保存为稳定文本。
- 星期、单双周模式使用稳定整数编码。
- 日期保存为 ISO 日期文本。
- 颜色保存为规范化的 `#RRGGBB`。
- 删除策略会在 Repository 课程中确定；默认优先归档学期，避免误删整个历史课表。
- 所有结构变化继续通过 `schema_migrations` 顺序升级。

## 7. 页面规划

### 课表首页

- 当前学期和当前教学周。
- 上一周、下一周和返回当前周。
- 周一至周日课程安排。
- 空课表与非教学周提示。
- 快速新增课程入口。

### 学期管理

- 学期列表。
- 创建、编辑、归档和切换当前学期。
- 学期开始日期和总周数。

### 课程与安排编辑

- 课程名称、教师、教室和颜色。
- 一个课程下可以增加多个上课安排。
- 星期、节次、周次和单双周选择。
- 保存前显示字段错误和冲突提示。

## 8. 响应式与 Android 后手

- 业务模型不使用鼠标坐标或桌面窗口尺寸。
- 宽屏使用完整周网格，窄屏可以切换为按天列表或横向滚动周视图。
- 主要操作不依赖悬停、右键和双击。
- 可点击控件高度不低于 `AppTheme.controlHeight`。
- 课程颜色始终配合可读文字，不只用颜色传递信息。
- 日期、教学周和星期计算放在 C++，QML 只绑定结果。
- SQLite 使用标准应用数据目录，不写死 Windows 路径。

## 10. 测试策略

- Domain：实体边界、文本规范化、周次和单双周规则。
- Application：内存 Repository、冲突组合、错误分类和固定查询次数。
- Infrastructure：临时 SQLite 数据库、外键、升级、排序和映射。
- Presentation：周切换、当前学期、表单状态和错误清理。
- QML：空课表、宽窄布局、编辑流程和 ViewModel 重绑定。

所有测试不得访问用户正式数据库。

## 11. MVP 完成标准

- 用户能够建立一个学期及其课程安排。
- 指定周只显示该周实际上课的课程。
- 冲突检测理解节次、周次和单双周。
- 重启后数据完整恢复。
- 空数据和错误状态有明确提示。
- 关键业务规则有自动测试。
- 640 像素窄窗口和桌面宽窗口均可操作。
- 文档、构建、测试和 Git 提交保持同步。

课表 MVP 完成后再统一进行 Windows Release 部署，并开始首次 Android 构建验证。
