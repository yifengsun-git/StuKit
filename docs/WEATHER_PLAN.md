# StuKit 天气模块开发计划

## 1. 模块目标

天气模块面向个人日常出行，提供选定城市的当前天气和短期预报。第一版继续在 Windows
完成，同时把领域模型、网络端口、JSON 解析和主要界面设计为可复用于 Android。

天气是独立功能模块，不依赖记账或课表业务。它只复用应用外壳、主题、通用按钮、
QSettings 和 Qt 的网络基础设施。

当前进度：第 47～52 课完成天气 MVP，第 71 课把供应商迁移到和风天气。Domain、异步
Application 端口、和风天气网络/JSON 基础设施、Presentation、应用组合根、响应式页面
和持久化离线缓存已经建立，并通过不访问公网的自动化测试。

## 2. MVP 功能范围

### 必须完成

- 通过中文或英文城市名搜索地点，而不是要求用户填写经纬度。
- 保存用户主动选择的城市，并在下次启动时恢复。
- 展示当前温度、体感温度、天气状态、湿度、降水和风况。
- 展示 7 天最高/最低温、天气状态和降水概率。
- 支持手动刷新、加载状态、错误状态和无网络时的最近缓存。
- 明确显示数据更新时间与和风天气数据署名。
- 宽窗口与 360～640 像素窄窗口都能完成搜索和查看。

### 后续增强

- 24 小时逐小时预报。
- 多城市收藏与排序。
- 空气质量、生活指数和恶劣天气提醒。
- Android 经用户授权后的设备定位。
- 桌面小组件和系统通知。

第一版默认不请求精确定位权限。城市搜索足以完成核心闭环，也不会在用户不知情时把
设备坐标发送给第三方。Android 定位以后作为可选入口加入。

## 3. 数据来源

当前实现使用和风天气的 GeoAPI 城市搜索、实时天气 v1 与每日预报 v1：

- API Host 必须使用控制台为项目分配的专属 Host，不能把旧公共 Host 写死。
- API Key 通过 `X-QW-Api-Key` 请求头传递，不放进 URL、源码或 Git。
- Windows 开发默认从环境变量读取；Android 可通过本机 CMake Cache 注入，配置方法见
  [和风天气配置说明](QWEATHER_SETUP.md)。
- 实时天气与每日预报并行请求，任一失败会取消另一条请求。
- 免费额度和服务可用性都不是无限的，因此继续保留本地缓存与请求取消机制。
- 页面必须展示 QWeather 和风天气名称、官网链接与接口返回要求的数据归因链接。

业务层不直接写死和风天气 JSON。供应商 URL、认证请求头和字段映射全部放在
Infrastructure，页面和领域模型不依赖供应商协议。

## 4. 核心模型

### `WeatherLocation`

保存地点名称、国家/地区、一级行政区、IANA 时区和 WGS84 经纬度。创建时验证坐标范围、
名称长度和时区 ID。

### `WeatherCondition`

把供应商天气代码归一为晴、多云、阴、雾、毛毛雨、雨、雪、阵雨和雷暴等稳定枚举。
QML 只消费稳定状态，不理解和风天气数字代码。原有 WMO 映射保留在 Domain 作为历史
兼容能力，和风天气映射位于它自己的 JSON 解析器中。

### `WeatherForecast`

包含：

- 地点；
- 当前观测/模型时间、温度、体感温度、湿度、降水和风况；
- 按日期排序且不重复的逐日预报；
- UTC 抓取时间。

领域工厂拒绝非有限数值、越界湿度/风向、最低温高于最高温、重复日期和非 UTC 抓取
时间，避免损坏的网络响应进入界面。

## 5. 架构

```text
src/features/weather/
  domain/          地点、天气状态、当前与逐日预报
  application/     城市搜索与获取预报端口、用例和错误分类
  infrastructure/  和风天气 HTTP、JSON 解析、缓存与设置
  presentation/    WeatherViewModel 与列表模型
  qml/             天气首页和地点搜索组件
```

依赖方向：

```text
QML -> Presentation -> Application -> Domain
Infrastructure --------------------------> Application + Domain
```

网络请求是异步的。Application 通过回调端口描述请求，不让 ViewModel 拼 URL，也不让
Infrastructure 操纵界面状态。每次请求带请求标识或取消语义，避免较慢的旧响应覆盖用户
刚选择的新城市。

## 6. 缓存与隐私

- 用户选中的地点保存到 QSettings；不需要新增业务数据库表。
- 最近一次成功预报保存为应用数据目录中的版本化 JSON 缓存。
- 缓存显示时明确标注更新时间；过期缓存只作为离线兜底，不冒充实时数据。
- 同一地点在短时间内重复进入页面优先复用缓存，避免浪费接口额度。
- 日志不输出完整请求 URL，以免无意记录用户选择的精确坐标。
- 第一版只上传用户主动选择城市的坐标；不读取系统位置。

## 8. 完成标准

- 用户无需了解经纬度即可找到并保存城市。
- 正常网络下能查看当前天气与 7 天预报。
- 请求失败不会清空仍可使用的缓存，也不会显示旧城市的新响应。
- 无数据、加载中、离线缓存和实时数据状态明确。
- 供应商数据解析有固定 JSON 样例测试，不依赖测试时访问公网。
- 界面保留数据来源署名和更新时间。
- Windows Debug 构建、QML 静态检查和全部自动化测试通过。
