# StuKit 项目计划

## 1. 项目目标

StuKit 首先面向 Windows 开发，首批功能为记账本和课表。在 Windows 版本
稳定后适配 Android，并尽量复用 C++ 业务代码、数据模型和 QML 组件。

第一版不追求功能数量，而是建立一套容易理解、能够测试、方便继续扩展的
工程基础。

当前主线已经调整为：先建立 Windows CI/CD 和可重复发布流程，再暂停新增功能，
集中重构桌面与 Android 共用的响应式界面。只有 UI 验收完成后，才评估下一项业务
功能。详细安排见 [CI/CD 与 Windows 发布说明](CI_CD.md) 和
[响应式 UI 重构计划](UI_REDESIGN_PLAN.md)。

## 2. 第一版范围

### 2.1 记账本 MVP

- 管理账户。
- 管理收入和支出分类。
- 新增、编辑、删除账单。
- 按月份查看和筛选流水。
- 显示月收入、月支出和结余。
- 使用 SQLite 保存数据。
- 备份和恢复本地数据。

基础数据分析包括默认分析和自定义分析：支持 2～24 个月范围、账户和分类过滤、
月度收支趋势、分类排行、账户资金流和上月对比。图表至少包含柱状、折线和排行形式，
分类较少时可切换环形图。暂不实现登录、云同步、OCR、多币种换算、预算、消费预测
和 AI 建议。

### 2.2 课表 MVP

- 管理学期。
- 管理课程、教师和教室。
- 设置星期、节次、起止周和单双周。
- 查看指定周课表。
- 检测课程时间冲突。

暂不实现教务系统导入、日历同步、桌面小组件和上课提醒。

## 3. 开发阶段

### 阶段 0：环境与基础知识

目标：能够独立打开、配置、构建和调试一个最小 Qt 工程。

验收标准：

- 已安装 Qt Creator、Qt 6 桌面组件、CMake 和编译器。
- 能说明 Qt Creator、Qt、编译器和 CMake 各自的作用。
- 能在 Debug 模式运行一个最小 Qt Quick 程序。

### 阶段 1：工程骨架

目标：建立不包含业务功能的应用外壳。

内容：

- CMake 工程和基础目录。
- 主窗口和页面导航。
- 浅色、深色主题。
- 日志和统一错误表示。
- SQLite 连接及数据库迁移机制。
- 最小单元测试目标。

验收标准：程序可以启动、切换空白功能页、初始化数据库并运行测试。

### 阶段 2：记账领域和数据层

目标：在没有实际页面的情况下完成并测试记账核心业务。

内容：

- Account、Category、Transaction 领域模型。
- 金额值对象和输入规则。
- Repository 接口及 SQLite 实现。
- 新增、修改、删除和查询账单用例。
- 月度汇总用例。

验收标准：所有核心规则和 Repository 集成测试通过。

### 阶段 3：记账界面

目标：完成一次完整的日常记账流程。

内容：

- 记账首页。
- 流水列表和筛选。
- 账单编辑页面。
- 账户和分类管理。
- 月度统计。

验收标准：用户可以从创建账户开始，完成记账、修改、查询和删除操作。

### 阶段 4：记账可靠性与数据可携带性

目标：让个人记账数据可以安全恢复并能被其他工具读取。

内容：

- 数据库事务和错误处理。
- 数据备份、恢复和导出。
- 数据库升级测试。

验收标准：数据库可以安全备份和恢复，全部流水可以导出，升级测试不会破坏原有
数据。

### 阶段 5：记账分析

目标：让用户能够理解长期收支变化和主要消费构成。

内容：

- 连续 2～24 个月收入、支出和结余趋势，默认最近 12 个月。
- 所选月份收入与支出分类排行。
- 按账户、分类和时间范围自定义数据范围。
- 所选月份账户资金流。
- 所选月份与上月的差额对比。
- 使用柱状图、折线图、排行图和可选环形图的响应式分析页面。
- 通用分析外壳与功能数据提供者分离，为饮食等模块复用图表组件。

验收标准：分析口径与自定义记账时区一致，金额保持整数分，空数据和跨年范围显示
正确，宽窄窗口都能清晰阅读。

### 阶段 6：课表模块

目标：按照相同架构完成课表 MVP。

当前状态：已完成。第 33～46 课已经建立领域模型、Repository 契约、冲突检测、版本 7
迁移、三个 SQLite Repository、Application、Presentation、真实组合根，以及学期、
课程和上课安排管理 UI；响应式周课表会在桌面显示星期/节次网格，并在窄屏切换为
按天列表。查看模式与学期排课编辑模式已经分离，网格支持点击添加和修改安排，并可
批量应用到全部、单周、双周或任意教学周；课表节数可扩展，课程资料可记录考核标准
和教学安排。课程与单条安排均提供确认后删除，数据库会级联清理关联排课。编辑模式
可以切换教学周观察实际课表，360 像素窄屏编辑与集成验收也已完成。当前还支持从
Excel/WPS 另存的 UTF-8 CSV 批量导入，并对空课程、空教学周和导入冲突进行安全防护。
节次名称和 `HH:mm` 起止时间可以独立设置，并会显示在查看和编辑网格中。详细安排见
[课表模块开发计划](SCHEDULE_PLAN.md)。

验收标准：能够建立一个学期的课程，查看指定周课表，并识别时间冲突。

### 阶段 7：天气模块

目标：提供城市搜索、当前天气、7 日预报和离线缓存，并保持 Windows/Android 共用
业务代码。第 47～52 课已完成领域模型、异步用例、Open-Meteo 基础设施、天气
ViewModel、应用组合根、响应式天气页面和版本化 JSON 离线缓存，天气 MVP 已完成。详细安排见
[天气模块开发计划](WEATHER_PLAN.md)。

### 阶段 8：待办任务模块

目标：集中管理作业、考试和竞赛任务，支持截止时间、提醒、完成归档、完成率统计，并
允许任务绑定课表中的课程。详细安排见[待办任务模块开发计划](TASKS_PLAN.md)。

第 53～61 课已完成任务领域、用例、SQLite schema 10 持久化、自定义分类、课程查询
适配器、滚轮日期时间选择、响应式任务页面和应用内到期提醒，目前进入人工验收。
系统级通知留到 Windows/Android 平台适配阶段。

### 阶段 9：CI/CD 与 Windows 发布

目标：让每次代码变更都经过自动构建和测试，并能从版本标签生成可运行的 Windows
发布包。

内容：

- GitHub Actions Windows MSVC 2022 自动构建。
- 运行全部 CTest 测试并阻止失败版本发布。
- Release 构建和 CMake 安装规则。
- 使用 Qt CMake 部署 API 收集 Qt、QML、平台、SQLite 和编译器运行时依赖。
- 对部署目录进行无界面启动冒烟测试。
- 普通构建保留短期 ZIP Artifact，`v*` 标签自动创建 GitHub Release。
- GitHub Actions 依赖由 Dependabot 定期检查。

验收标准：push/PR 自动构建并通过全部测试，`v0.1.0` 这类与项目版本一致的标签能
产生 `StuKit-windows-x64.zip`；压缩包在没有 Qt 开发环境的 Windows 电脑上可以
启动并完成核心操作。

### 阶段 10：响应式 UI 重构

目标：在不改变领域逻辑和现有功能范围的前提下，建立一致、清晰且可触摸的桌面与
移动界面。

内容：

- 统一颜色、字体、间距、圆角、按钮状态和输入控件尺寸。
- 桌面使用侧边导航，窄屏使用底部导航或抽屉，不再把桌面菜单压缩隐藏。
- 首页、记账、课表、待办、天气和分析页面逐一进行宽窄屏重排。
- 弹窗宽度受窗口约束，表单在软键盘出现时仍能滚动到当前输入项。
- 增加关键宽度 QML 集成测试和 Windows/Android 人工截图验收。

验收标准：详细标准见 [响应式 UI 重构计划](UI_REDESIGN_PLAN.md)。UI 验收未完成前
不开发新业务模块。

### 阶段 11：Android 发布适配

目标：复用核心代码完成 Android 版本。

内容：

- 响应式布局和移动端导航。
- 触摸交互检查。
- Android 应用生命周期和数据目录适配。
- 权限、备份、签名和真机测试。

验收标准：Windows 与 Android 使用相同的 Domain 和 Application 代码，
平台差异集中在界面布局和平台适配层。

## 5. 每个功能的完成定义

一个功能只有同时满足以下条件才算完成：

- 需求和异常情况已经说明。
- 代码符合架构依赖规则。
- 核心逻辑有自动测试。
- Debug 构建无新增警告。
- 已进行人工操作验证。
- 相关文档已同步更新。
- Git 提交内容单一且信息清晰。
