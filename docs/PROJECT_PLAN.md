# StuKit 项目计划

## 1. 项目目标

StuKit 首先面向 Windows 开发，首批功能为记账本和课表。在 Windows 版本
稳定后适配 Android，并尽量复用 C++ 业务代码、数据模型和 QML 组件。

第一版不追求功能数量，而是建立一套容易理解、能够测试、方便继续扩展的
工程基础。

## 2. 第一版范围

### 2.1 记账本 MVP

- 管理账户。
- 管理收入和支出分类。
- 新增、编辑、删除账单。
- 按月份查看和筛选流水。
- 显示月收入、月支出和结余。
- 使用 SQLite 保存数据。
- 备份和恢复本地数据。

暂不实现登录、云同步、OCR、多币种换算和复杂预算分析。

### 2.2 课表 MVP

- 管理学期。
- 管理课程、教师和教室。
- 设置星期、节次、起止周和单双周。
- 查看指定周课表。
- 检测课程时间冲突。

暂不实现教务系统导入、日历同步、桌面小组件和上课提醒。

## 3. 开发阶段

### 阶段 0：环境与基础知识

目标：能够独立打开、配置、构建和调试一个最小 Qt 工程。

验收标准：

- 已安装 Qt Creator、Qt 6 桌面组件、CMake 和编译器。
- 能说明 Qt Creator、Qt、编译器和 CMake 各自的作用。
- 能在 Debug 模式运行一个最小 Qt Quick 程序。

### 阶段 1：工程骨架

目标：建立不包含业务功能的应用外壳。

内容：

- CMake 工程和基础目录。
- 主窗口和页面导航。
- 浅色、深色主题。
- 日志和统一错误表示。
- SQLite 连接及数据库迁移机制。
- 最小单元测试目标。

验收标准：程序可以启动、切换空白功能页、初始化数据库并运行测试。

### 阶段 2：记账领域和数据层

目标：在没有实际页面的情况下完成并测试记账核心业务。

内容：

- Account、Category、Transaction 领域模型。
- 金额值对象和输入规则。
- Repository 接口及 SQLite 实现。
- 新增、修改、删除和查询账单用例。
- 月度汇总用例。

验收标准：所有核心规则和 Repository 集成测试通过。

### 阶段 3：记账界面

目标：完成一次完整的日常记账流程。

内容：

- 记账首页。
- 流水列表和筛选。
- 账单编辑页面。
- 账户和分类管理。
- 月度统计。

验收标准：用户可以从创建账户开始，完成记账、修改、查询和删除操作。

### 阶段 4：可靠性与 Windows 发布

目标：让应用能够安全地交给其他 Windows 用户使用。

内容：

- 数据库事务和错误处理。
- 数据备份、恢复和导出。
- 数据库升级测试。
- Release 构建和 Windows 部署包。

验收标准：在没有开发环境的 Windows 电脑上可以安装和运行，升级版本不会
破坏原有数据。

### 阶段 5：课表模块

目标：按照相同架构完成课表 MVP。

验收标准：能够建立一个学期的课程，查看指定周课表，并识别时间冲突。

### 阶段 6：Android 适配

目标：复用核心代码完成 Android 版本。

内容：

- 响应式布局和移动端导航。
- 触摸交互检查。
- Android 应用生命周期和数据目录适配。
- 权限、备份、签名和真机测试。

验收标准：Windows 与 Android 使用相同的 Domain 和 Application 代码，
平台差异集中在界面布局和平台适配层。

## 5. 每个功能的完成定义

一个功能只有同时满足以下条件才算完成：

- 需求和异常情况已经说明。
- 代码符合架构依赖规则。
- 核心逻辑有自动测试。
- Debug 构建无新增警告。
- 已进行人工操作验证。
- 相关文档已同步更新。
- Git 提交内容单一且信息清晰。
