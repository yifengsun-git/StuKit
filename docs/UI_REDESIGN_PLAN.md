# StuKit 响应式 UI 重构计划

> 当前进度：UI-0、UI-2、UI-3 已完成；UI-1 已建立主题、导航、卡片、表单和弹窗组件
> 基线；UI-4 已完成安全区、短横屏、软键盘和返回键的代码基线。UI-5 自动构建、
> 60 项回归测试和启动冒烟已通过，当前等待 Windows 可视化与 Android 真机人工验收。
> 现状与处理状态见 [UI 现状审计](UI_AUDIT.md)。

## 1. 重构原因

当前应用的业务功能已经比较完整，但界面是在功能开发过程中逐页增长的，缺少统一的
布局规则。桌面布局直接压缩到手机后出现了以下问题：

- 首页菜单和部分操作按钮在窄屏被遮挡或挤出可见区域。
- 按钮、输入框和弹窗宽度不一致，局部内容超过弹窗边界。
- 桌面侧边栏、密集工具栏和大表格不适合触摸操作。
- 控件虽然能显示，但视觉层级、留白和点击反馈不统一。
- 页面各自判断宽度，缺少共享断点和通用响应式容器。

本阶段只调整信息架构、布局、视觉样式和交互反馈，不改变领域规则、数据库结构，
也不增加新的业务模块。

## 2. 设计原则

1. **一套业务，两套外壳**：Domain、Application 和 ViewModel 继续复用；桌面和窄屏
   可以采用不同导航与排版，不强迫手机复制桌面外观。
2. **按可用宽度响应**：主要布局根据容器宽度切换，不只判断 `Qt.platform.os`，方便
   桌面缩放窗口和 Android 横竖屏共同使用。
3. **操作必须可见**：主操作不能依赖 hover，也不能因为空间不足直接消失；次要操作
   可以进入“更多”菜单。
4. **内容优先**：每页只保留一个明确的主操作，设置和低频管理入口降低视觉权重。
5. **触摸友好**：手机按钮和可点击区域目标高度不低于 48 dp，控件之间留出误触间距。
6. **弹窗受窗口约束**：所有 Dialog/Popup 使用最大宽高，内容过长时内部滚动，软键盘
   出现后当前输入项仍可访问。
7. **状态完整**：普通、悬停、按下、选中、禁用、加载、空数据和错误状态都有明确反馈。

## 3. 目标尺寸矩阵

| 类型 | 验收尺寸 | 主要布局 |
| --- | --- | --- |
| Windows 最小窗口 | 960 × 640 | 紧凑桌面布局 |
| Windows 常用窗口 | 1280 × 720、1440 × 900 | 侧边导航与多栏内容 |
| Windows 高分屏 | 1920 × 1080，125%/150% 缩放 | 限制内容最大宽度，避免过度拉伸 |
| Android 窄屏 | 360 × 800 dp | 单栏、底部导航、全宽页面 |
| Android 常用屏 | 412 × 915 dp | 单栏或局部双栏 |
| Android 横屏 | 800 × 360 dp | 紧凑双栏，处理安全区 |

建议共享断点先定义为：窄屏 `< 720`、中等 `720～1099`、宽屏 `>= 1100`。实际值在
首页和课表原型验证后再固定到主题单例中。

## 4. 实施顺序

### 阶段 UI-0：现状审计与基线

- 在目标尺寸矩阵下逐页截图。
- 记录遮挡、溢出、无法点击、层级混乱和触摸面积不足的问题。
- 为首页导航、共享弹窗和每个业务模块建立问题清单。
- 暂不进行零散美化，先确认统一规则。

完成标准：所有现存页面都有桌面和窄屏基线，首页菜单隐藏问题可以稳定复现。

状态：已完成。结构问题已记录，应用外壳和首页的 P0 问题已经修复。

### 阶段 UI-1：设计令牌与共享组件

- 扩展 `AppTheme`：断点、内容最大宽度、字体层级、间距、圆角、阴影和状态颜色。
- 整理 `AppButton`，统一主按钮、次按钮、文本按钮和危险按钮。
- 建立响应式页面容器、卡片、工具栏、空状态、错误状态和受约束弹窗。
- 输入框、下拉框、日期时间选择器统一尺寸和验证信息位置。

完成标准：业务页面不再各自硬编码常用颜色、圆角和弹窗宽度。

状态：进行中。主题断点、触摸尺寸、状态颜色、导航按钮、功能卡片、内容卡片、文本
输入、长文本输入、下拉框和受约束弹窗已完成；日期时间选择、统一页面容器、空状态和
错误状态仍待继续整理。

### 阶段 UI-2：应用外壳与首页导航

- 桌面宽屏保留侧边导航，并明确当前模块。
- 手机使用底部导航；超过可用数量的入口进入“更多”页面或抽屉。
- 顶部栏只显示当前页标题与必要操作，不重复放置导航。
- 首页改为尺寸一致的功能卡片，全部模块入口在 360 dp 宽度可见且可滚动。
- 返回行为在桌面、Android 系统返回键和页面内部按钮之间保持一致。

完成标准：开始界面不存在隐藏菜单；旋转屏幕和调整窗口后，当前页面与导航状态不丢失。

状态：代码完成，等待 Windows 可视化验收和 Android 真机验收。

### 阶段 UI-3：业务页面重排

按共享程度和使用频率依次处理：

1. 记账首页、流水列表、账单编辑和账户/分类管理。
2. 待办清单、筛选、任务编辑与分类管理。
3. 课表周网格、按天列表、编辑工具栏和课程资料。
4. 天气搜索、当前天气和预报卡片。
5. 数据分析筛选、图表切换和图表降级显示。

宽屏优先使用“列表 + 详情/编辑”或多栏布局；窄屏使用单任务页面和全屏编辑，避免在
一个手机页面中同时塞入所有管理功能。

完成标准：每个模块在目标尺寸下无水平溢出，主操作始终可见，长列表和长表单可以
完整滚动。

状态：进行中。记账首页已完成第一轮重排：主操作、设置管理、数据工具和统计摘要建立
清晰层级，数据工具默认折叠，统计摘要支持一、二、四列响应式布局。共享弹窗现在限制
最大高度并自动滚动，记账和待办长表单的操作区固定在底部。待办首页的主操作、统计和
筛选层级也已完成第一轮重排。课程表已统一学期选择、周次导航和编辑入口，学期、课程、
排课与删除弹窗会限制在窗口内，节次表单会在窄屏纵向排列；这些页面仍需结合 Windows
可视化与 Android 软键盘、横屏场景验收。天气页已统一搜索、结果、错误、缓存和空状态
卡片，当前天气与七日预报受共享最大内容宽度约束。数据分析页已统一筛选和图表选择器，
排行与环形图在窄屏使用纵向结构，至此 UI-3 计划内页面全部完成第一轮重排。

### 阶段 UI-4：移动端细节

- 统一 Safe Area、状态栏、导航栏和横屏边距。
- 验证软键盘弹出、焦点移动、滚轮选择器和返回键。
- 去除依赖鼠标 hover 才能理解的操作，并补充按压/选中反馈。
- 处理课表触摸命中、图表手势冲突和弹窗关闭方式。
- 检查 Android 字体、中文换行和系统字体缩放。

完成标准：所有核心流程可以只使用触摸完成，不需要鼠标语义。

状态：代码基线完成。窗口四边安全区均已接入，低高度横屏会自动使用紧凑底部导航；
Android Activity 使用 `adjustResize`，共享弹窗会在键盘或焦点变化时把当前输入项滚动到
可见区域；返回键按“收起键盘、关闭弹窗或分析页、返回首页、交给系统退出”的层级处理。
Qt 6.10.3 arm64-v8a Debug APK 已成功生成。课表触摸手感、图表手势、字体缩放与中文
换行仍需在 UI-5 真机验收中确认。

完成标准：CI 全部通过，目标尺寸不存在遮挡或溢出，Windows 与 Android 核心流程
均通过人工验收。

状态：自动验收基线通过，人工验收未完成。目标尺寸、操作顺序和问题记录格式已整理到
[人工验收清单](ACCEPTANCE_CHECKLIST.md)。只有清单中的 Windows 与 Android 项目实际

## 5. 新功能冻结规则

UI-0 到 UI-5 期间不新增业务模块。只允许以下变更进入主线：

- CI/CD、构建和部署修复。
- 阻塞现有流程的缺陷修复。
- UI 结构、视觉、交互和可访问性改进。
- 为上述改动补充的测试和文档。

完成 UI-5 后再重新评估下一模块；评估时同时考虑使用频率、维护成本、桌面与移动端
复用程度，而不是直接继续增加首页入口。
