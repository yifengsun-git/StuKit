# 第四十五课：排课防错与 CSV 批量导入

## 本课目标

本课继续完善课表模块，不进入部署或其他功能模块。重点解决四个真实使用问题：

- 没有可用课程时点击网格会触发空容器断言。
- 创建安排时不清楚当前正在安排哪门课程。
- 学期开始日期和节数调整的含义、入口不够明确。
- 手工逐条录入整学期课程成本较高。

## 1. 为什么会出现 `back() called on empty vector`

课程安排需要从“教学周集合”得到第一周和最后一周。空集合没有首尾元素，如果直接
调用 `front()` 或 `back()`，Debug 运行时就会触发断言。

本课在三层增加保护：

1. 编辑网格只有在存在课程且已经选中课程时才允许点击。
2. 打开创建弹窗前再次校验所选课程，并明确显示“当前课程”。
3. C++ ViewModel 和 Domain 在读取首尾周次前都先拒绝空集合。

界面校验改善用户体验，C++ 校验保证即使以后增加别的界面入口，也不会把非法数据
传入领域对象。两者不能互相替代。

## 2. 学期表单与编辑入口

学期编辑表单现在明确标注：

- **学期名称**：用于区分不同学期。
- **学期开始日期（第 1 周的周一）**：课表用它计算每个教学周对应的日期。
- **学期总周数**：限制课程安排允许选择的最大周次。

“增加一节”和“减少一节”只在进入“编辑课表”后显示。它们调整的是当前课表网格的
可见节数，不会创建或删除课程，也不会修改已经保存的上课安排。

## 3. CSV 一键导入

Qt 本身不提供 `.xlsx` 解析器。当前阶段选择 UTF-8 CSV，是因为 Excel 和 WPS 都能
直接另存为该格式，同时不引入额外桌面依赖，更利于后续 Android 构建。

可直接复制并填写[课表导入模板](../templates/schedule-import-template.csv)。必填列为：

| 列名 | 示例 | 规则 |
| --- | --- | --- |
| 课程名称 | 高等数学 | 同一学期同名课程会复用 |
| 星期 | 周一 | 支持周一～周日或 1～7 |
| 开始节次 | 1 | 最小为 1 |
| 结束节次 | 2 | 不得小于开始节次 |
| 教学周 | `1-18` | 也支持 `1;3;5;7` |

教师、教室、颜色、考核标准和教学安排是可选列。英文表头也支持：
`course_name`、`teacher`、`location`、`color`、`weekday`、
`start_period`、`end_period`、`weeks`、`assessment`、`teaching_plan`。

操作步骤：

1. 在 Excel 或 WPS 中打开模板并填写课程。
2. 另存为 **CSV UTF-8（逗号分隔）**。
3. 在 StuKit 选择目标学期，进入“编辑课表”。
4. 点击“导入 CSV”并选择文件。
5. 查看成功数量；若某行有误，界面会提示对应行号。

导入前会先解析并校验全部行。写入过程中如果出现课程冲突或存储错误，导入器会按
相反顺序撤销本次已经创建的安排和课程；原有课程资料不会被删除。

## 4. 架构位置

- `IScheduleImportService` 是 Application 层端口，只描述导入能力和错误类型。
- `CsvScheduleImportService` 位于 Infrastructure 层，负责文件、CSV 解析和仓储协调。
- `ScheduleManagementViewModel` 将文件 URL 与中文结果提示提供给 QML。
- `ScheduleGridEditor.qml` 只负责文件选择和界面反馈。

这样将来若决定支持原生 `.xlsx`，只需增加另一个基础设施实现，不需要让 QML 或领域
模型依赖 Excel 库。

## 5. 验收点

- 没有课程时，网格不可编辑并提示先创建、选择课程。
- 创建和编辑安排的弹窗明确显示课程名称。
- 空教学周不会触发 `front()` / `back()` 断言。
- 节数按钮仅在编辑课表时出现。
- CSV 能创建课程及多条安排，并支持任意教学周集合。
- 文件中出现冲突时，本次导入不留下半成品。
- 360 像素窗口下排课弹窗不超出页面视口。

下一课仍留在课表模块，计划完善“节次名称与具体起止时间”，让第 1 节不仅是数字，
还能显示例如 `08:00–08:45`。这会采用独立配置模型，不改变现有课程冲突的节次规则。
