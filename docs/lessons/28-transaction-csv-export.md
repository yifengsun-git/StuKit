# 第二十八课：流水 CSV 导出

## 本课定位

第二十七课已经能完整备份和恢复 StuKit 数据库。数据库备份适合灾难恢复，但不适合
直接用 Excel、WPS 或其他工具查看。本课将增加只读的 CSV 流水导出，为个人数据
分析和跨软件使用提供标准文本格式。

## 1. 本课目标

- 导出全部历史流水，而不只导出当前月份或当前筛选结果。
- 输出收支类型、金额、账户、分类、发生时间和备注。
- 金额继续从整数分格式化，不经过浮点数。
- 同时输出 UTC 时间和用户记账时区中的本地时间，避免时间含义丢失。
- 正确转义逗号、双引号和换行。
- 使用 UTF-8 编码，让中文内容可被常用表格软件读取。
- 导出失败不修改数据库，也不影响当前界面状态。
- 文件选择保持跨平台边界，为 Android 内容 URI 适配留出入口。

## 2. 备份和 CSV 的区别

```text
SQLite 备份：完整、可恢复、程序使用
CSV 导出：可阅读、可分析、不能完整恢复应用状态
```

CSV 不包含数据库迁移信息，也不会作为 StuKit 的导入格式。用户需要恢复全部数据时，
仍应使用第二十七课生成的 `.sqlite` 文件。

## 3. 实际数据来源

通过独立查询用例一次读取：

- 全部账单。
- 全部账户。
- 全部分类。

用例负责把 UUID 关联为稳定名称，并保留已归档账户和分类。CSV 写入器只负责字段
顺序、文本转义和文件提交，不重新查询数据库或计算业务数据。

## 4. CSV 格式

第一版列顺序：

```text
账单ID,类型,金额,账户,分类,UTC时间,记账时区时间,时区,备注
```

- 收入和支出使用明确中文文本。
- 金额固定两位小数。
- UTC 时间使用带毫秒 ISO 8601。
- 本地时间包含日期和时分秒。
- 文本字段按 CSV 规则转义。
- 行结尾使用 CRLF，兼容 Windows 表格工具。

## 5. 已实现架构

```text
QML FileDialog
  -> DataMaintenanceViewModel
  -> GetTransactionExportData
  -> CsvTransactionWriter
  -> QSaveFile
```

查询放在 Application，文件编码与写入放在 Infrastructure，文件选择和提示仍由
应用 ViewModel/QML 负责。Domain 实体和 SQLite 表结构无需修改。

具体职责：

- `GetTransactionExportData` 读取全部流水、账户和分类，关联可读名称并按时间倒序。
- `CsvTransactionWriter` 负责金额格式、CSV 转义、UTF-8 BOM、CRLF 与原子提交。
- `AccountingModule` 组合查询用例与写入器，使用用户当前记账时区。
- `DataMaintenanceViewModel` 将文件对话框返回的 URL 转换成本地路径并提供状态提示。
- QML 只负责选择保存位置和触发操作。

导出文件使用 UTF-8 BOM，主要是为了让 Windows 上的常用表格软件更稳定地识别中文；
所有字段统一加双引号，字段内双引号写成两个双引号，因此逗号和换行不会破坏列结构。
写入使用 `QSaveFile`，只有全部内容成功写完才替换目标文件。

## 6. 自动测试

- 空数据库仍会生成 UTF-8 表头。
- 已归档账户和分类仍能关联原名称，流水按时间稳定倒序。
- 收支类型和整数分金额格式正确。
- UTC 与 UTC+08:00 本地时间同时输出。
- 逗号、引号、中文和多行备注正确转义。
- 已有目标默认受保护，明确覆盖时通过原子提交替换。
- 应用组合根到 `DataMaintenanceViewModel` 的真实 SQLite 导出链路已覆盖。

本课验证结果：MSVC2022 构建成功，27/27 自动测试通过，QML lint 通过。

## 7. 本课 UI 小优化

- 备份、恢复和 CSV 导出从基础资料按钮中移到独立“数据工具”卡片。
- 卡片说明数据库备份和 CSV 的用途差异。
- 四张金额摘要卡片在宽窗口显示四列，在窄窗口自动显示两列。
- 导出成功或失败信息留在数据工具区域，操作结果更容易找到。
