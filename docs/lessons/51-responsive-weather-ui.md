# 第五十一课：响应式天气界面

## 1. 本课目标

本课把第 50 课提供的 `WeatherViewModel` 接入 QML，让用户可以完成第一条可见的天气
使用链路：搜索城市、选择地点、查看当前天气、阅读 7 日预报并手动刷新。

页面只消费 ViewModel 的属性和操作，不拼接网络 URL，也不解析供应商 JSON。

## 2. 导航接入

天气加入应用的三个入口：

- 首页功能按钮；
- 左侧导航抽屉；
- `StackLayout` 中的 `WeatherHomePage`。

主窗口标题会随页面切换为“天气”。窗口最小宽度从 640 调整到 360 像素，因此桌面端
也能直接检查未来 Android 所需的窄屏布局。首页功能入口改用响应式网格，增加天气后
不会在窄窗口横向溢出。

## 3. 页面组成

`WeatherHomePage` 包含：

```text
城市搜索框 + 搜索按钮
  -> 搜索结果列表
  -> 加载或错误提示
  -> 当前天气卡片
  -> 7 日预报网格
  -> Open-Meteo / CC BY 4.0 署名
```

搜索框要求至少两个字符，搜索期间禁止重复提交。地点结果显示城市、行政区和国家，
点击后由 ViewModel 保存地点并获取预报。刷新按钮只在已经选择城市且当前没有请求时
可用。

## 4. 当前天气与 7 日预报

`CurrentWeatherCard` 展示：

- 城市和地区；
- 当前温度与天气状态；
- 体感温度；
- 湿度、降水和风况；
- 数据更新时间。

`DailyForecastGrid` 展示日期、星期、天气状态、最低/最高温和降水概率。它只接收
ViewModel 已经格式化的列表，不了解 WMO 天气代码。

页面底部提供可点击的 Open-Meteo 来源链接和 CC BY 4.0 署名，避免数据来源在正式页面
中丢失。

## 5. 响应式规则

页面以 640 像素为布局断点：

- 宽屏下搜索框与按钮同排，当前天气指标为三列，逐日预报为横向 7 列；
- 窄屏下搜索按钮换到下一行，天气指标为两列，逐日预报改为单列卡片；
- 页面整体放在 `ScrollView` 中，360×640 窗口仍可触达全部内容；
- 交互按钮沿用至少 44 像素高度，方便未来触摸操作。

响应式变化只发生在 QML，Domain、Application 和 Infrastructure 无需区分 Windows 与
Android。

## 6. 状态设计

- 没有地点：提示用户先搜索并选择城市；
- 搜索中：禁用输入和按钮，并显示“搜索中”；
- 刷新中：显示进度指示和刷新文字；
- 请求错误：显示中文错误卡片；
- 已有预报后刷新失败：错误提示和旧预报同时保留。

最后一种状态很重要：短暂网络错误不应把用户刚看到的天气清空。第 52 课会把这份
兜底能力从“本次运行内存”扩展为“关闭应用后仍可恢复”的版本化 JSON 缓存。

## 7. 自动化验证

新增 `app.weather_qml` 集成测试，使用假搜索服务和假预报服务，完全离线验证：

- 360 与 960 像素布局切换；
- 搜索按钮的触摸高度和空状态；
- 城市输入、搜索结果渲染与地点选择；
- 当前天气卡片与 7 条逐日预报；
- Open-Meteo 署名；
- 刷新失败后错误状态与已有预报并存。

## 8. 本课完成标准

- 首页和导航可以进入天气页面；
- 用户可以搜索城市并查看当前天气和 7 日预报；
- 加载、空状态和错误状态清晰；
- 360～960 像素宽度下页面没有固定桌面布局依赖；
- QML 静态检查、天气界面测试和完整工程构建通过。
