# 第二十七课：SQLite 数据备份与恢复

## 本课定位

第二十六课完成后，记账 MVP 已能创建、管理、查询和筛选数据。下一阶段不急着增加
更多页面，而是先保护用户已经录入的数据。本课将建立本地数据库备份与恢复流程，
并把平台文件选择与数据操作分开，为 Windows 发布和后续 Android 适配打基础。

## 1. 本课目标

- 将正在使用的 SQLite 数据库安全备份到用户选择的位置。
- 恢复前验证候选文件确实是 StuKit 数据库且版本可支持。
- 恢复前自动保留当前数据的安全副本。
- 恢复过程中关闭数据库连接，成功后重新初始化记账模块与页面状态。
- 失败时保留原数据库，并向用户显示可理解的错误。
- QML 只负责选择文件、二次确认和显示结果，不直接复制数据库文件。
- 文件路径能力保持跨平台，不把 Windows 路径规则写进业务层。

## 2. 为什么不能直接复制正在使用的数据库

SQLite 可能正在执行事务，数据库也可能启用辅助日志文件。直接在资源管理器中复制
主文件，不能保证得到一致快照。备份应通过 SQLite 提供的一致性机制生成，恢复则
必须在所有连接释放后进行。

第一版计划使用明确的基础设施服务：

```text
QML FileDialog
  -> app/DataMaintenanceViewModel
  -> DatabaseBackupService
  -> SQLite / filesystem
```

该服务属于 Infrastructure，因为它依赖数据库连接与文件系统；ViewModel 负责把
结果转换为界面状态，Domain 和记账用例不感知备份文件。

## 3. 备份策略

- 备份开始前确认数据库已完成迁移且连接可用。
- 使用 SQLite 一致性快照能力写入新的目标文件。
- 不覆盖源数据库。
- 目标已存在时要求用户先明确确认。
- 完成后重新打开备份文件，检查关键表和迁移版本。
- 备份文件使用可识别的日期时间名称，但名称不参与数据正确性判断。

## 4. 恢复策略

恢复是高风险操作，按以下顺序执行：

1. 只读验证候选数据库及其迁移版本。
2. 为当前数据库创建自动回退副本。
3. 释放 ViewModel、Repository 和 SQLite 连接。
4. 用已验证文件替换当前数据库。
5. 重新初始化组合根并刷新所有页面状态。
6. 如果替换或初始化失败，恢复自动回退副本。

界面必须说明“恢复会替换当前数据”，并要求二次确认。测试不会只验证成功路径，
也会故意提供损坏文件、普通 SQLite 文件和不支持版本的 StuKit 文件。

## 5. Android 后手

Windows 与 Android 的主要差异是用户如何选择和授权访问文件。数据库验证、快照、
关闭连接和重新初始化流程仍可复用。文件选择结果在边界处转换为本地可操作路径；
如果 Android 返回内容 URI，则由平台适配层先复制到应用临时目录，再交给同一个
备份恢复服务，避免把 Android API 扩散到记账模块。

## 9. 实现说明

### 一致性备份

`SqliteBackupService` 使用 SQLite 的 `VACUUM INTO` 创建一致快照，先写入目标目录的
临时文件，再执行 `PRAGMA quick_check`、迁移历史和关键表验证。验证通过后使用
`QSaveFile` 原子提交到用户选择的目标，避免中途失败留下半个备份文件。

服务会拒绝把活动数据库备份到自身。目标已存在时，底层默认拒绝覆盖；界面使用
系统保存对话框完成覆盖确认后才显式允许替换。

### 恢复与回退

恢复候选文件必须满足以下条件：

- 是结构完整的 SQLite 数据库。
- 包含连续的 StuKit 迁移历史。
- 包含对应版本需要的业务表。
- 数据库版本不高于当前程序支持的版本 3。

候选文件通过验证后，`AccountingModule` 先在应用数据目录的 `backups/` 中创建
`pre-restore-*.sqlite` 安全快照，然后按依赖顺序销毁 ViewModel、用例、Repository
和数据库连接。替换使用 `QSaveFile` 原子提交；重新初始化失败时，会用安全快照回退
并再次打开原数据。

恢复会重建四个记账 ViewModel。`DataMaintenanceViewModel` 通知 `main.cpp` 把新对象
重新设置到 QML 根属性，避免界面继续引用已经销毁的对象。

### Git 数据保护

正式数据库默认位于 `QStandardPaths::AppDataLocation`，不在 Git 仓库。`.gitignore`
同时新增 `*.sqlite`、`*.db` 及 SQLite WAL/SHM 文件规则，即使以后把数据库复制到
项目目录，也不会被普通 `git add` 意外提交。

## 10. 实现与验证结果

- 首页增加“备份数据”和“恢复数据”入口。
- 备份使用系统保存文件对话框，默认补全 `.sqlite` 后缀。
- 恢复使用系统打开文件对话框，并在替换当前数据前二次确认。
- 损坏文件、普通非 StuKit 数据库和未来版本数据库会在关闭当前连接前被拒绝。
- 恢复成功后账户、分类、流水、余额和当前月份页面状态重新加载。
- 恢复前安全快照会保留在应用数据目录，便于额外人工找回。
