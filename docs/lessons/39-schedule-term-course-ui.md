# 第三十九课：学期与课程管理 UI

## 本课成果

本课把课表从独立 C++ 功能接入了正式应用。现在用户可以使用真实 SQLite 完成：

- 新建、编辑、归档和恢复学期。
- 新建、编辑课程名称、教师、教室和颜色。
- 为一门课程添加或编辑多条上课安排。
- 设置星期、节次、起止周和每周/单周/双周。
- 查看冲突课程和首次冲突周。
- 重启应用后恢复全部课表数据。

课表首页也不再是占位页，已经提供学期选择、上下周、返回当前周和按顺序展示的课程
列表。完整桌面周网格和 Android 按天布局留到下一课。

## 1. GetScheduleSetup

管理页面需要同时读取学期、课程和上课安排，因此新增 `GetScheduleSetup` Application
用例。它一次获取三个 Repository 快照，并将任一查询失败统一转换为
`StorageFailure`。成功但没有数据仍然返回三个空列表。

Presentation 不直接查询 SQLite，也不分别协调三个 Repository。

## 2. 管理列表模型

`ScheduleManagementModels` 包含三个 QML 列表模型：

- `AcademicTermListModel`：UUID、名称、开始日期、总周数、归档状态。
- `CourseListModel`：UUID、所属学期、名称、教师、教室、颜色。
- `CourseMeetingListModel`：星期、节次、周次、单双周和可读摘要。

模型只负责角色转换，不包含保存和冲突规则。

## 3. ScheduleManagementViewModel

管理 ViewModel 负责当前学期和课程选择，并把表单输入转换为三个保存用例的请求。
保存成功后会重新读取管理快照，同时发出 `dataChanged`，让周课表自动刷新。

错误被转换为用户可读文本，包括：

- 学期、课程或安排字段无效。
- 缩短学期后已有安排越界。
- 已归档学期禁止修改课程和安排。
- 课程不能被普通编辑操作移动到另一学期。
- 安排超过总周数。
- Repository 保存或查询失败。

冲突不是普通错误字符串。`conflicts` 属性会提供冲突课程名、安排 UUID、星期、节次和
首次冲突周，QML 可以逐条展示，且冲突数据不会写入数据库。

## 4. ScheduleModule 与数据库生命周期

新增的 `ScheduleModule` 独立组装：

- 三个课表 SQLite Repository。
- 学期、设置和指定周查询用例。
- 三个保存用例。
- 周课表与管理 ViewModel。

它接收已打开的共享 `QSqlDatabase`，不创建第二个用户数据库。当前应用组合根统一持有
`ScheduleModule`，在数据库恢复前先销毁课表对象，恢复后再重建。这避免 Windows 下
旧数据库连接阻止文件替换，也保证记账和课表会从同一个备份一起恢复。

## 5. QML 管理界面

`ScheduleHomePage.qml` 负责课表浏览，`ScheduleManagementPanel.qml` 负责管理流程。
管理面板按“学期 → 课程 → 上课安排”逐级展示：

- 学期表单输入名称、ISO 日期和 1～30 周。
- 课程表单输入基本资料和 `#RRGGBB` 颜色。
- 安排表单使用选择框和数字控件，适合鼠标与触摸。
- 归档学期仍可查看，但新增和编辑按钮被禁用。
- 冲突明细直接显示在管理面板中。

本课没有加入课程删除。删除会级联影响多条安排，需要单独设计二次确认和历史数据
语义，不能把危险操作混入普通编辑按钮。

## 本课小结

课表已经拥有从 QML 到 SQLite 的第一条完整用户链路。下一课将把当前按顺序显示的课程
升级为桌面周网格，并为窄窗口提供按天列表，同时补充 QML 响应式验收。
