# 第六十五课：响应式弹窗与待办首页重排

## 本课目标

本课完成两个连续目标：先解决记账和其它模块都会遇到的长弹窗问题，再使用第六十四课
建立的共享组件重排待办首页。业务用例、数据库和提醒规则均不改变。

## 一、共享弹窗能力

`AppDialog` 新增了以下通用行为：

- 宽度不能超过当前页面，并保留 16 px 安全边距；
- 高度不能超过当前页面，并保留 16 px 上下边距；
- 内容超过可用高度时自动出现纵向滚动；
- 禁止横向滚动，表单控件只能使用弹窗内容宽度；
- 暴露 `contentScrollable`，方便集成测试验证长内容是否进入滚动状态。

记账模块的账单编辑器和账户/分类管理器使用固定底部操作区。用户滚动表单或管理列表
时，保存、取消和关闭按钮不会被内容推到屏幕外。管理列表还会根据页面高度在 180～360
px 之间调整，兼顾桌面窗口与 Android 横屏。

## 二、待办首页信息层级

待办页完成以下重排：

1. 页面内容居中，并限制在 1180 px 最大宽度内。
2. 标题、说明和“新建任务”组合成首要操作卡片。
3. 360 px 下主操作改为单列，按钮不会与标题争夺横向空间。
4. 统计区保留窄屏两列、桌面四列布局。
5. 搜索、分类、归档显示和新增分类集中到筛选卡片。
6. 窄屏默认折叠筛选，桌面端自动展开，减少手机首屏拥挤。
7. 搜索、分类选择、任务标题、说明、优先级和课程选择接入共享表单组件。
8. 任务编辑器、分类弹窗和删除确认弹窗接入 `AppDialog`。
9. 任务编辑器的保存和取消按钮固定在弹窗底部。

## 三、为什么筛选在手机上默认折叠

待办页最常用的操作是查看近期任务、完成任务和新建任务。搜索与分类筛选很有用，但并
不需要永久占用手机首屏。默认折叠可以先展示任务状态和清单；需要查找历史任务时只需
点击一次“展开筛选”。桌面空间充足，因此筛选保持展开，避免增加操作步骤。

折叠只属于界面状态，不会改变 ViewModel 中的搜索条件或归档设置，也不会影响任务数据。

## 四、自动验证

`app.accounting_home_qml` 增加了低高度窗口场景，检查账单编辑和管理弹窗的宽高上限，
并确认长账单表单进入滚动状态。

`app.tasks_qml` 增加了以下检查：

- 360 px 下首要操作卡片不超宽，筛选默认折叠；
- 960 px 下切换为桌面布局、四列统计并自动显示筛选；
- 360 × 480 下任务编辑器不超过可用区域且内容可滚动；
- 用户展开筛选后，筛选内容可以正常显示。
