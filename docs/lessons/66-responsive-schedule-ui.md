# 第六十六课：响应式课程表与排课弹窗

## 本课目标

本课继续 UI-3，在不改动课程、学期、排课和冲突检测规则的前提下，重新整理课程表
查看页、编辑入口、周次导航和管理弹窗，使同一套界面同时适合 Windows 与 Android。

## 一、课程表首页重排

课程表首页现在使用与记账、待办一致的内容宽度和页面边距：

- 页面内容最大宽度限制为 1180 px，宽屏不会被无限拉开；
- 学期选择、课程资料和编辑入口集中在首要操作卡片；
- 周次、实际日期范围和上一周/当前周/下一周集中在周导航卡片；
- 增加、减少节次只在编辑模式出现，避免查看状态下误操作；
- 360 px 下按钮和选择框自动换为纵向结构；
- 查看模式继续使用“窄屏按天列表、宽屏周网格”，没有改变原有使用习惯。

## 二、管理与排课表单

学期、课程、上课安排和删除确认弹窗都接入 `AppDialog`。这带来统一的行为：

1. 弹窗四周始终保留 16 px 安全边距。
2. 内容高度超过窗口时在弹窗内部滚动。
3. 课程资料中的考核标准、教学计划不会把弹窗推到屏幕外。
4. 输入框、长文本输入和课程选择使用共享表单组件。
5. 手机宽度下排课操作按钮改为网格排列，删除操作单独占一行。
6. 节次名称与起止时间在窄屏改为纵向表单，桌面仍保持双栏。

课程表网格本身仍允许横向滚动。这是有意保留的交互：星期与节次构成二维表格，强行
把七天压缩到 360 px 会让课程内容无法阅读；窄屏的日常查看仍优先使用按天列表。

## 三、响应式边界

本课没有为 Android 复制另一套业务界面。页面继续根据容器宽度决定布局，因此桌面
缩放窗口、Android 竖屏和 Android 横屏都经过同一条代码路径。课程表 ViewModel、
Application 用例、Repository 和 SQLite 数据均未改变。

## 四、自动验证

`app.schedule_qml` 现在覆盖：

- 640、960、1280 px 下的按天列表、周网格和最大内容宽度；
- 查看模式与编辑模式切换；
- 编辑状态下的周次切换和节数增减；
- 360 px 下排课弹窗不超过页面宽高；
- 360 × 480 下课程资料管理弹窗保留安全边距；
- 没有课程时禁止创建排课，避免再次触发空集合断言。
