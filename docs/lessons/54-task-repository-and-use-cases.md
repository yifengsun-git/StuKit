# 第五十四课：任务 Repository 与 Application 用例

## 本课目标

在 TaskItem 领域规则之外，建立“应用可以做什么”：保存、查询、完成、归档、恢复、
重新打开和删除任务，并计算清单统计。所有用例先对 Repository 接口编程，不接 SQLite。

## 本课完成内容

### 1. `ITaskRepository`

Repository 契约提供保存、按 UUID 查询、查询全部和物理删除。Domain 与 Application 只
依赖接口；第 55 课的 SQLite 类只是其中一种实现，测试使用内存实现。

### 2. 保存任务

`SaveTask` 同时服务新建和编辑：请求没有 ID 时生成 UUID；编辑时保留原创建时间、状态
与完成时间，避免用户修改标题后把已完成任务偷偷变回待办。所有请求仍要重新通过
`TaskItem::create` 校验。

### 3. 状态迁移

允许的迁移固定为：

```text
待完成 -> 已完成 -> 已归档
   ^          ^          |
   |          +----------+ 恢复归档
   +------------- 重新打开
```

不能把待完成任务直接归档，也不能重复完成。归档不是删除，完成时间会继续保留。

### 4. 查询和完成率

`GetTaskOverview` 支持分类、课程和关键字过滤，默认隐藏归档任务。结果按状态、截止时间、
优先级和创建时间稳定排序，并返回待完成、已完成、已归档、逾期数量和完成率。

归档任务虽然默认不在主列表显示，但仍属于已完成任务，会计入完成率。筛选分类或课程
时，统计与列表使用同一数据范围。

### 5. 明确删除

`DeleteTask` 是物理删除用例，先确认任务存在再调用 Repository。界面后续必须二次确认；
日常整理优先使用完成和归档。

## 测试覆盖

- 新建生成 UUID、编辑保留创建时间。
- 完成、归档、恢复和重新打开完整状态链。
- 非法状态跳转。
- 分类过滤、默认隐藏归档、逾期计数、排序和完成率。
- 删除成功、不存在 ID 和空 ID。
