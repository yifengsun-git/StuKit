# 第五十五课：任务 SQLite 持久化

## 本课目标

把第 54 课通过内存仓库验证的任务用例接到共享 SQLite 数据库，使任务在应用退出后仍然
保留，同时保证已有记账和课表数据可以安全升级。

## 本课完成内容

### 1. 数据库迁移版本 8

`SqliteDatabase::CurrentSchemaVersion` 从 7 升级到 8。迁移创建 `tasks` 表以及状态/截止
时间、分类和课程 ID 索引。已有版本 7 数据库只执行新增迁移，不重建记账或课表表格。

表约束再次表达关键领域规则：标题非空、枚举值范围合法、提醒必须有截止时间且不能
更晚、课程 ID 与名称快照成对出现、完成状态与完成时间一致。数据库约束不是领域模型
的替代，而是防止外部工具或未来代码写入明显损坏的数据。

任务的 `course_id` 没有 SQLite 外键。课程被删除后，任务仍保留 ID 和名称快照，不会被
级联删除；这是跨模块历史数据的有意设计。

### 2. `SqliteTaskRepository`

Repository 实现负责：

- 用 `INSERT ... ON CONFLICT DO UPDATE` 保存新建和编辑任务；
- 正确绑定可空的截止时间、提醒、课程和完成时间；
- 把时间以带 `Z` 的 ISO 8601 UTC 文本保存；
- 从数据库读取后重新通过 `TaskItem::create` 校验；
- 稳定查询全部任务和明确物理删除。

空 `QString` 在 Qt 中可能是“空字符串”或“null 字符串”。写入 `NOT NULL` 列前会统一成
真正的空字符串，避免合法的无说明/无课程任务触发数据库约束。

### 3. 升级与备份兼容

原有迁移幂等、旧版本升级、失败回滚和数据库备份测试已经同步到 schema 8。未来版本
数据库识别边界相应变成 9，版本 8 现在属于本应用可读格式。

## 测试覆盖

- schema 8、`tasks` 表和三个索引创建成功。
- 完整任务保存、读取、更新、列表和删除。
- 可空截止时间/提醒/课程字段往返。
- 已归档状态和完成时间往返。
- 旧迁移、失败回滚、备份校验保持兼容。
