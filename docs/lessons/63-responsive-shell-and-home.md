# 第六十三课：响应式应用外壳与首页

## 本课目标

本课开始执行 UI 重构计划，先解决所有模块共同依赖的应用外壳和首页，而不是逐页修改
颜色。业务层、ViewModel 和数据库均未改变。

## 完成内容

1. 在 `AppTheme` 中建立 720/1100 断点、最大内容宽度、触摸尺寸和完整交互颜色。
2. 将 Qt Quick Controls 固定为可定制的 `Basic` 样式，消除 Windows 原生样式忽略
   自定义控件的问题。
3. 桌面端使用常驻侧边栏，当前模块拥有明确选中状态。
4. 窄屏使用始终可见的底部导航，首页、记账、课表、待办和天气不再藏在抽屉中。
5. 首页改为可滚动的响应式功能卡片：360 px 单列，较宽窗口双列。
6. 增加 `AppNavigationButton` 和 `FeatureCard` 两个共享组件。
7. 新增 `app.shell_qml` 集成测试，覆盖宽度变化和首页导航信号。

## 为什么不继续沿用抽屉菜单

抽屉适合放低频入口，但 StuKit 当前五个入口都是一级模块。如果唯一的“菜单”按钮在
安全区、标题或系统缩放下被遮挡，用户会失去全部导航能力。底部导航在手机上持续可见，
侧边导航在桌面上利用横向空间，两者共享同一个 `currentPage` 状态和业务页面。

## 验收结果

- MSVC 2022 Debug 构建通过。
- 应用离屏启动 5 秒，无 QML 警告或加载错误。
- 59/59 项测试通过。
- 没有新增或修改数据库结构。
