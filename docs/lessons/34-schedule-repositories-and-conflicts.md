# 第三十四课：课表 Repository 与冲突检测

## 本课目标

在第 33 课实体规则的基础上，定义课表数据的存取契约，并在不使用 SQLite 的情况下
完成冲突检测。这样可以先证明业务算法正确，再把同一接口交给数据库实现。

## 1. 计划增加的 Repository 接口

- `IAcademicTermRepository`：保存、按 UUID 查询和查询全部学期。
- `ICourseRepository`：保存、按 UUID 查询和按学期查询课程。
- `ICourseMeetingRepository`：保存、按 UUID 查询和按课程查询安排。

接口属于 Domain，只描述业务需要的能力，不包含 SQL 语句、表名或 SQLite 连接。
测试目录会提供内存实现，正式应用后续提供 SQLite 实现。

## 2. 冲突检测用例

计划建立 `DetectScheduleConflicts`。两条安排必须同时满足以下条件才冲突：

1. 课程属于同一学期。
2. 星期相同。
3. 节次闭区间重叠。
4. 周次范围有交集。
5. 交集内至少有一周同时匹配双方的每周、单周或双周模式。

例如：

- 单周与双周在相同节次不冲突。
- 每周与单周在单周会冲突。
- 星期不同不冲突。
- 周次相同但节次首尾不重叠时不冲突。

## 3. 错误边界

用例需要区分：

- 输入 UUID 无效。
- 课程或学期不存在。
- Repository 查询失败。
- 安排自身无效。
- 安排超出所属学期总周数。
- 成功且没有冲突。
- 成功并返回一个或多个冲突。

“没有冲突”是正常成功结果，不能和存储失败使用同一种空值表示。

## 4. 测试重点

- Repository 新增、更新、查询和稳定筛选契约。
- 每周/单周/双周的所有组合。
- 节次边界、周次边界和不同星期。
- 同一课程多条安排及不同课程之间的冲突。
- Repository 失败时返回稳定错误。
- 用例不访问 SQLite，也不启动 QML。

## 5. 本课完成标准

- 三个 Repository 接口不依赖具体数据库。
- 内存测试实现能够支持后续 Application 测试。
- 冲突算法覆盖主要组合和边界。
- 全工程构建与测试通过。
- 文档同步更新。

完成后，第 35 课会为课表增加 SQLite 数据库迁移、外键和索引。
