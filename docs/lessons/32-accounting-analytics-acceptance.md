# 第三十二课：分析页验收与记账 MVP 收尾

## 本课目标

第 31 课已经完成分析页面的真实图表和筛选交互。本课不再扩张业务功能，而是通过
自动化与人工场景验收分析页面，修复边界问题，并给记账 MVP 建立明确的完成标准。

## 1. QML 集成测试

计划使用 Qt Quick Test 覆盖：

- 空数据库下所有图表显示可解释的空状态。
- 6、12、24 个月切换后图表点数同步变化。
- 柱状图/折线图、排行/环形图切换不会丢失数据。
- 账户与分类选择会更新条件摘要。
- “不限”和“恢复默认”的语义一致。
- ViewModel 被数据库恢复流程重建后，页面能绑定新对象。

测试只验证页面契约，不在 QML 测试中复制记账聚合算法。

## 2. 真实数据验收

准备一个仅用于测试的隔离数据库，覆盖：

- 同月存在收入和支出。
- 结余为正、零和负数。
- 多个账户和多个分类。
- 归档账户和归档分类仍出现在历史分析中。
- 跨年月份以及 UTC 边界附近的账单。
- 小于 1 元、大额和没有数据的月份。

不会复制或修改用户正式数据库。

## 3. 响应式与可用性

至少检查 640×480、960×640 和宽桌面窗口：

- 关键按钮不被遮挡。
- 筛选面板在窄窗口默认折叠。
- 账户资金流在窄窗口不会横向溢出。
- 24 个月标签保持可辨认。
- 深色与浅色主题下文字、网格和图表颜色可读。

同时检查键盘焦点、按钮文字和触摸高度，为 Android 迁移保留基础。

## 4. 记账 MVP 完成标准

- 账户与分类创建、编辑、归档和恢复。
- 账单新增、查看、编辑、删除和组合筛选。
- 自定义记账时区。
- 账户余额和月度汇总。
- SQLite 备份、恢复及 CSV 导出。
- 默认分析、自定义筛选和多种图表。
- 自动测试、启动检查和课程文档同步通过。

## 5. 本课不做什么

- 不增加预算、预测或 AI 建议。
- 不保存自定义报表模板。
- 不进行 Windows Release 打包。
- 不修改数据库结构。

完成本课后，第 33 课开始课表模块的领域建模，包括学期、课程、周次、星期和节次。
