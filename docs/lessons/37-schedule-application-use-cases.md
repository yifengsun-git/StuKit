# 第三十七课：课表 Application 用例

## 本课目标

把已有 Domain、冲突检测和 Repository 组合成用户可以执行的业务流程。仍不写 QML，
先通过内存 Repository 测试创建、修改和查询规则。

## 1. 学期用例

计划提供：

- 创建学期。
- 修改名称、开始日期和总周数。
- 归档或恢复学期。
- 查询使用中与历史学期。

缩短学期总周数时，如果现有安排超出新范围，操作必须返回明确错误，不能制造不一致
数据。

## 2. 课程与安排用例

- 创建和修改课程基本资料。
- 创建和修改一条上课安排。
- 保存安排前检查所属课程、所属学期和总周数。
- 调用 `DetectScheduleConflicts`，区分无冲突、冲突和存储失败。
- 编辑安排时保留 UUID，并排除自身冲突。

冲突结果应作为正常业务结果返回，让以后界面决定是阻止保存还是提示用户确认；本课
先采用安全默认值：存在冲突时不保存。

## 3. 指定教学周查询

计划建立 `GetWeeklySchedule`：

- 输入学期 UUID 和教学周数。
- 验证周数处于该学期范围。
- 读取该学期课程及对应安排。
- 使用 `occursInWeek()` 过滤单双周。
- 返回包含课程名、教师、教室、颜色、星期和节次的展示 DTO。
- 结果按星期、起始节次、课程名稳定排序。

Application 返回普通数据结构，不返回 `QAbstractItemModel`；列表模型留到 Presentation。

## 4. 错误分类

至少区分：

- 输入无效。
- 学期、课程或安排不存在。
- 安排超过学期总周数。
- 课程冲突。
- Repository 查询失败。
- Repository 保存失败。

空学期和指定周没有课程都是成功的空结果，不是错误。

## 5. 自动测试

- 创建与更新保留 UUID 和未修改字段。
- 学期归档、恢复及缩短周数保护。
- 安排的每周、单周、双周过滤。
- 冲突时不发生部分保存。
- 不同学期互不影响。
- 缺失关联和所有 Repository 失败路径。
- 查询次数保持固定且可解释。

完成后，第 38 课为课表建立 Presentation 列表模型与 ViewModel。
