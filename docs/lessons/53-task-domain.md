# 第五十三课：待办任务领域模型

## 本课目标

先不接数据库和界面，建立待办模块最稳定的业务词汇与规则：任务、分类、优先级、状态、
截止时间、提醒和可选课程绑定。

## 本课完成内容

### 1. 三组稳定枚举

- `TaskPriority`：低、普通、高、紧急。
- `TaskCategory`：作业、考试、竞赛。
- `TaskStatus`：待完成、已完成、已归档。

枚举属于 Domain，数据库和 QML 后续都只能映射它们，不能各自创造另一套状态含义。

### 2. `TaskItem` 聚合

`TaskItem::create` 是任务进入系统前的统一校验入口。它会整理首尾空白并拒绝空标题、
过长文本、空 UUID、非法 UTC 时间、晚于截止时间的提醒，以及状态和完成时间不一致。

截止时间设计为可选：作业、考试通常有截止时间，但个人工具包也可以记录“有空整理
笔记”这类没有固定日期的待办。提醒依赖截止时间，不能单独存在。

### 3. 课程绑定不是领域耦合

任务只保存可选的课程 UUID 和课程名称快照，不引用 `schedule::Course`。两者必须同时
存在或同时为空。名称快照保证课程以后改名或删除时，历史作业仍然可读。

### 4. 时间判断

`isOverdue(nowUtc)` 只会把尚未完成且截止时间早于当前时刻的任务视为逾期；
`reminderIsDue(nowUtc)` 只检查待完成任务。已完成和已归档任务不会继续触发提醒。

## 为什么所有持久化时间使用 UTC

用户可能修改系统时区，也可能以后把数据迁移到 Android。统一保存 UTC 可以避免同一
任务在不同设备上变成不同绝对时刻；Presentation 再按用户选择的时区格式化显示。

## 测试覆盖

- 合法任务的创建与文本整理。
- 无截止时间、无提醒、无课程的通用待办。
- 标题、说明和 UUID 边界。
- UTC、提醒顺序和完成时间规则。
- 课程 ID 与名称快照的一致性。
- 逾期与提醒状态判断。
