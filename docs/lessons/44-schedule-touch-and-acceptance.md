# 第四十四课：触摸与集成验收

## 本课目标

完成课表 MVP 的窄屏交互和集成验收，并让编辑界面也能按教学周查看实际课表。

## 本课实现

### 1. 编辑模式保留周次导航

进入“编辑课表”后，上一周、下一周和返回当前周仍然可用。编辑网格绑定的是当前所选
教学周的数据，因此切换周数时可以直接观察这一周实际会出现哪些课程。课程安排的
`activeWeeks` 仍保存完整教学周集合，切换查看周数不会修改排课数据。

这一设计把两个概念分开：

- 编辑模式决定“能不能修改课程安排”。
- 当前教学周决定“网格正在展示哪一周”。

### 2. 窄屏编辑布局

- 顶部学期选择与编辑按钮在窄窗口中改为纵向排列。
- 节数增减区域在窄窗口中使用两列布局。
- 排课编辑工具栏在窄窗口中改为单列。
- 教学周快捷选择在窄窗口中改为两列，具体周次改为三列。
- 排课弹窗限制在当前可用宽高内，并使用滚动区域承载较长的周次列表。
- 主要按钮与周次选项继续使用主题定义的最小控件高度，方便后续触摸操作。

悬停阴影只用于桌面端反馈，添加、编辑、删除等关键操作均可通过点击完成，不依赖
鼠标悬停、右键或双击。

### 3. 集成验收

QML 集成测试新增以下路径：

- 编辑模式中使用上一周、下一周观察不同周次的课程数量。
- 360 × 640 窄窗口中进入编辑模式并打开排课表单。
- 验证导航按钮、周次快捷按钮的触摸目标高度。
- 结合 Application 与 Repository 测试验证自定义周次、删除和数据一致性。

现有 SQLite 测试继续覆盖数据库迁移、重建后的数据恢复、外键关系和删除一致性；测试
使用临时数据库，不会访问用户正式数据。

## 验收结果

- MSVC Debug 完整构建通过。
- `all_qmllint` 通过且无新增 QML 警告。
- 全部自动测试通过。
- 编辑模式可以切换教学周，并保持排课编辑能力。
- 桌面宽屏和 360 像素窄屏都具备完整的核心操作入口。

课表 MVP 至此完成。下一阶段可以根据实际需求继续增加课表功能，或进入 Windows
Release 打包；Android 构建验证仍放在 Windows 版本稳定之后。
