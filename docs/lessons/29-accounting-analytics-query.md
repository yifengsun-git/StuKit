# 第二十九课：可自定义的记账分析查询

## 本课结果

本课已经完成记账分析的 Application 层基础，并在应用导航中增加独立的“数据分析”
板块。当前页面是分析入口和能力说明，真实图表、筛选控件及 ViewModel 将在第 30、
31 课接入。

本课没有修改数据库结构。分析数据由现有账户、分类和流水实时聚合，因此不会产生
另一份容易失真的统计数据。

## 1. 默认分析与自定义分析

进入分析页面后，系统将提供一套开箱即用的默认方案：

- 默认截止月份：用户记账时区中的当前月份。
- 默认时间范围：最近 12 个自然月。
- 默认数据范围：全部账户、全部分类。
- 默认指标：收入、支出和结余。
- 默认内容：月度趋势、上月对比、分类排行和账户资金流。

用户也可以在同一套查询能力上自定义：

- 截止月份。
- 2～24 个月的统计范围，界面会优先提供 6、12、24 个月快捷选项。
- 一个或多个账户；不选择表示全部账户。
- 一个或多个分类；不选择表示全部分类。
- 后续页面中的指标和图表形式。

“默认分析”不是另一套写死的代码，而是自定义分析的一组默认参数。这样新增筛选条件
时，只需维护一条查询链路。

## 2. 为什么单独建立数据分析板块

数据分析现在与“记账本”和“课表”并列为一级入口。这里分为两层：

```text
通用分析外壳
  页面布局、时间范围选择、指标卡、图表容器、空状态、颜色和交互
                         ↑
功能数据提供者
  记账：GetAccountingAnalytics
  饮食：未来的 GetNutritionAnalytics
  学习：未来的 GetStudyAnalytics
```

可复用的是分析页面和图表组件，不是记账领域对象。未来开发饮食控制模块时，它应提供
自己的营养数据 DTO，例如热量、蛋白质、碳水和体重趋势；通用图表只读取标题、标签、
数值和颜色等展示数据。这样不会让饮食模块依赖 `Transaction` 或 `Category`。

## 3. 图表规划

分析不以饼图为唯一形式。不同问题使用不同图表：

| 分析问题 | 默认形式 | 可选形式 | 原因 |
| --- | --- | --- | --- |
| 各月收入与支出 | 分组柱状图 | 折线图 | 便于比较同月两个金额，也能观察长期趋势。 |
| 月结余变化 | 折线图 | 柱状图 | 正负变化和转折更清楚。 |
| 分类构成 | 横向排行条 | 环形图 | 分类多时排行更易读；分类少时可切换环形图。 |
| 账户资金流 | 分组条形图 | 排行列表 | 可同时查看各账户收入、支出和净流入。 |
| 当前月与上月 | 指标卡 | 小型柱状图 | 直接突出差额和变化方向。 |

图表只负责展示，不能自己查询 SQLite 或重新统计金额。底层金额始终使用整数分，只有
交给图表坐标轴时才临时转换为 `double`。

## 4. Application 请求与返回值

新增文件：

```text
src/features/accounting/application/GetAccountingAnalytics.h
src/features/accounting/application/GetAccountingAnalytics.cpp
```

请求模型的核心字段是：

```cpp
struct GetAccountingAnalyticsRequest
{
    QDate selectedMonth;
    int monthCount{12};
    QTimeZone timeZone;
    std::vector<QUuid> accountIds;
    std::vector<QUuid> categoryIds;
};
```

空的账户或分类 ID 列表表示不过滤。结果包含：

- `MonthlyAnalyticsPoint`：连续月份的收入、支出和结余。
- `CategoryAnalyticsItem`：所选月的分类名称、类型、金额、笔数和归档状态。
- `AccountAnalyticsItem`：所选月的账户收入、支出、净流入、笔数和归档状态。
- `AccountingAnalytics`：统一承载月度点、收入分类、支出分类和账户资金流。

上月差额和分类百分比属于展示派生数据，将由 Presentation 根据这些原始聚合结果计算，
避免 Application 层混入具体图表格式。

## 5. 查询和聚合流程

```text
GetAccountingAnalytics::execute(request)
  -> 校验月份、2～24 个月范围、时区和筛选 UUID
  -> 按用户记账时区计算自然月边界
  -> 转换为 UTC 查询边界
  -> ITransactionRepository::findOccurredBetween（一次）
  -> IAccountRepository::findAll（一次）
  -> ICategoryRepository::findAll（一次）
  -> 验证筛选 ID 和每笔流水的关联关系
  -> 应用账户、分类筛选
  -> 生成连续零值月份
  -> 聚合月度、所选月分类和账户资金流
  -> 稳定排序并返回
```

不能按月份循环查询数据库。无论请求 2 个月还是 24 个月，Repository 查询次数都保持
固定。

## 6. 统计口径与边界

- 月结余 = 月收入 - 月支出。
- 账户净流入 = 账户收入 - 账户支出。
- 所有业务金额使用 `Money` 的 `qint64` 整数分。
- 每次累加都检查溢出，失败时不返回部分结果。
- 流水先转换到用户自定义记账时区，再判断所属月份。
- 没有流水的月份仍返回零值，图表横轴不会断裂。
- 已归档账户和分类保留历史名称及归档状态。
- 分类按金额降序，金额相同时按名称和 UUID 稳定排序。
- 账户资金流按支出、收入、名称和 UUID 稳定排序。

结果错误为：

- `InvalidInput`：日期、月份数量、时区或筛选 ID 无效。
- `StorageFailure`：Repository 查询失败、流水缺少账户/分类，或分类类型与流水不一致。
- `ArithmeticOverflow`：任一金额累加超出 `qint64`。

## 8. 自动测试

新增 `GetAccountingAnalyticsTest.cpp`，验证：

- 空数据也返回连续零值月份，且三种 Repository 各查询一次。
- 月度、分类和账户数据聚合正确。
- 已归档账户和分类仍保留可读名称。
- 账户与分类过滤可以同时生效。
- UTC+08:00 跨年边界归属正确。
- 月份数量和不存在的筛选 ID 被拒绝。
- 查询失败和缺失关联返回存储错误。
- 整数累加溢出返回稳定错误。

验收结果：

- [x] 支持连续 2～24 个月的月度趋势数据。
- [x] 支持账户和分类自定义过滤。
- [x] 返回收入/支出分类排行与账户资金流。
- [x] 用户记账时区决定月份边界。
- [x] 已归档关联仍保持可读。
- [x] 查询次数不随月份数量增加。
- [x] 金额使用整数分并检查溢出。
- [x] 全部 28 个测试通过。
- [x] QML 静态检查和应用启动检查通过。
