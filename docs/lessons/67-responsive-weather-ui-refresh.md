# 第六十七课：天气页响应式重排

## 本课目标

本课继续 UI-3，统一天气页的搜索、状态提示、当前天气和未来预报层级。网络请求、缓存、
已保存城市和 Open-Meteo 解析逻辑保持不变。

## 一、页面结构

天气页现在采用和其它模块一致的页面规则：

- 内容居中且最大宽度为 1180 px；
- 窄屏使用 16 px 页面边距，桌面使用 24 px；
- 搜索城市是页面主操作，标题、说明、输入框和按钮集中在首要操作卡片；
- 360 px 下搜索框与按钮纵向排列，桌面端并排显示；
- 搜索结果、网络错误、离线缓存和未选择城市使用统一内容卡片；
- 已保存城市和刷新状态放在当前天气之前，刷新入口始终可见。

## 二、天气内容

当前天气卡片在窄屏减少内边距，温度与地点仍保持主次关系。湿度、降水和风况继续使用
两列布局，但第三项会跨越整行，避免只占左半边形成不平衡的空白。

未来 7 天在窄屏继续使用纵向列表，在桌面端使用七列卡片。数据来源署名在手机上左对齐、
桌面上右对齐，链接和许可信息均保留。

## 三、为什么没有增加“自动定位”

本阶段只调整 UI。自动定位会引入 Android 位置权限、Windows 定位服务、隐私提示和新的
平台适配接口，属于新功能而不是界面重排，因此继续使用用户主动搜索并保存城市的流程。

## 四、自动验证

`app.weather_qml` 在原有搜索、选择地点、加载七日预报、刷新失败后保留旧数据的测试上，
新增以下布局断言：

- 360 px 下搜索卡片不超过 328 px；
- 搜索输入框满足 48 px 触摸高度；
- 360/960 px 下分别使用紧凑和桌面布局；
- 1440 px 下页面内容不会超过 1180 px。

## 验收结果

- Qt 6.10.3、MSVC 2022 Debug 完整构建通过。
- 应用离屏启动 5 秒，保持运行且标准输出、错误输出均为空。
- 天气专项 QML 测试 4/4 通过，无新增 QML 警告。
- 全部 60/60 项自动测试通过。
- 没有修改天气服务、缓存格式、数据库或领域规则。
- 本课未创建 Git 提交。
