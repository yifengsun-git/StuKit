# 第六十九课：Android 移动交互细节

## 本课目标

本课完成 UI-4 的代码基线：让应用在 Android 刘海屏、手势导航、短横屏和软键盘场景下
仍保持可导航、可输入、可返回，同时不改变任何业务规则和数据库结构。

## 一、安全区与短横屏

主窗口原本已经避让顶部状态栏和底部手势区，本课进一步补齐左右安全区。这样手机横屏
时，页面内容、侧边导航和底部导航不会贴入刘海、圆角或系统手势区域。

响应式判断也不再只看宽度。当窗口高度低于 520 px 时，即使宽度达到 800 px，也会使用
紧凑外壳和底部导航。它解决了 Android 800 × 360 dp 横屏被误判为桌面布局、侧栏占用
大量高度的问题。页面当前模块不会因横竖屏切换而重置。

## 二、软键盘与长表单

项目新增了 Android 清单覆盖文件，并保持 Qt 模板所需的占位符、Activity、Provider 和
权限注入点不变。Activity 的 `windowSoftInputMode` 设置为 `adjustResize`：软键盘弹出时
系统缩小 Qt 窗口的可用区域，而不是直接覆盖表单底部。

共享 `AppDialog` 会监听窗口焦点和输入法键盘区域变化。如果焦点位于弹窗的滚动内容中，
弹窗会把对应输入框滚动到可见区域。这个行为由一个共享组件提供，记账、待办和课表的
编辑表单无需各自实现键盘避让。

## 三、统一返回层级

Android 返回键现在遵循下面的优先级：

1. 软键盘可见时先收起键盘，不离开当前表单；
2. 共享弹窗打开时由弹窗拒绝并关闭；
3. 数据分析页返回记账首页；
4. 其他业务模块返回应用首页；
5. 已位于首页时不消费事件，让 Android 执行系统默认退出行为。

桌面端的 Escape 键也复用弹窗关闭逻辑。测试中的任务页面被放入真实的离屏
`QQuickWindow`，避免在没有 Window/Overlay 的环境里直接打开 Popup，并验证统一返回请求
确实可以关闭任务编辑器。

## 四、Android 构建验证

本课使用现有 `Android Qt 6.10.3 Clang arm64-v8a` 配置完成完整交叉编译和 Gradle 打包：

- Android SDK：Platform 36；
- NDK：27.2.12479018；
- JDK：`D:\ComputerProject\jdk17\jdk-17.0.20.1+1`；
- Gradle：8.14.3；
- 构建类型：Debug、arm64-v8a。

生成的调试 APK 位于构建目录的
`android-build/build/outputs/apk/debug/android-build-debug.apk`。该文件属于可再生构建产物，
不提交到 GitHub。

构建日志里的 `QtQuick.Controls.Windows/macOS/iOS` 扫描警告来自跨平台样式探测，不表示
Android 缺少运行模块。SDK XML 和 Gradle 9 兼容提示来自 Android 命令行工具与 Gradle
插件版本组合，目前不影响 Gradle 8.14.3 成功打包，后续升级工具链时统一处理。

## 五、验收边界

自动构建能证明代码和清单可打包，但不能替代真机视觉验收。下一阶段仍需检查：

- 刘海屏、三键导航和手势导航下的四边安全区；
- 中文输入法弹出后，每个长表单的焦点是否始终可见；
- 竖屏与 800 × 360 dp 横屏切换后，导航和当前页是否保持；
- 返回键依次关闭键盘、弹窗和页面，不产生误退出；
- 课表格子触摸命中、图表滚动手势、系统字体 100%/130%/150% 下的换行。
