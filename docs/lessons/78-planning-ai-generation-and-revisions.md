# 第 78 课：AI 规划生成与 Markdown 版本

## 本课目标

- 使用 DeepSeek 或 OpenAI 兼容接口分析当前项目资料。
- 让用户在发送前确认范围，并能取消进行中的请求。
- 把模型结果保存成不可变历史版本，而不是覆盖上一份规划。
- 支持手动编辑、Markdown 预览和 `.md` 导出。

## 请求流程

```text
选择规划和资料
  -> 用户补充本次偏好
  -> 确认服务地址、模型和资料数量
  -> 构建系统约束与带 S1/S2 编号的资料上下文
  -> POST /chat/completions
  -> 解析 Markdown
  -> 保存 PlanRevision
  -> 编辑 / 预览 / 导出
```

一次请求最多发送约 12 万字符，超过部分不上传。系统提示要求模型把资料当作数据、对不
确定内容标注假设，并用 `[S1]`、`[S2]` 引用来源。这个约束可以降低误用风险，但不能
保证模型结论正确，用户仍需对照学校和活动官方文件核验。

## 版本规则

`PlanRevision` 在同一项目内从 1 开始递增，保存 Markdown、服务商、模型、引用资料 UUID
和 UTC 创建时间。手动点击“保存新版本”与 AI 生成都创建新记录；历史版本可以随时加载，
不会被后续编辑覆盖。

## Markdown 与 Mermaid

编辑区和预览区并列显示；窄窗口自动改为上下布局。Qt 能渲染常用 Markdown，Mermaid
代码块在应用内暂按代码展示，导出到 `.md` 时原样保留，可在支持 Mermaid 的编辑器或
平台渲染。导出使用临时文件提交机制，降低写入中断导致文件损坏的风险。

## 错误处理

目前对无效密钥、模型或地址不存在、频率/额度限制、超时和无法解析的响应提供用户可读
提示。调用采用非流式响应以优先完成稳定闭环；流式输出、自动重试和厂商原生结构化响应
属于后续增强。
